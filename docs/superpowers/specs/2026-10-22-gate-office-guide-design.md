# 校門口手機找處室：第一階段設計

日期：2026-10-22。狀態：使用者已同意產品方向，本文件供實作前檢視。

## 目標與情境

家長、來賓已站在大溪國中正門，使用手機找到處室並依現場地標前往。成功條件是能選定目的地、理解從正門出發的分段路線，以及辨認入口和樓層。

網站不使用手機即時定位。路線卡進度由使用者操作，不將虛擬人物位置當成使用者位置；自動帶路僅作為路線預覽。

## 已確認的設計取捨

- 保留校慶首頁、校園手冊與既有探索功能，新增醒目的「我在校門口，找處室」入口。
- 手機以分段路線卡為主，3D 可展開；預設不自動播放人物帶路。
- 相較沿用全畫面 3D，路線卡較方便邊走邊看；相較另建獨立網站，共用現有資料能減少處室位置不同步。
- 可分享的校門模式入口供後續製作 QR Code；本階段不印製或張貼。

## 操作流程

1. 進入校門模式：顯示「從正門出發的參考路線」，提供常用處室及搜尋。此畫面不要求先載入完整 3D 才可操作。
2. 選擇目的地：顯示處室、建築、樓層，以及「從校門開始帶路」。辦事情境捷徑只列有資料佐證的對應，不猜測承辦處室。
3. 開始指引：顯示步驟數、當前地標與一項動作；提供「上一步」「下一步」「查看完整路線」「查看 3D」及「重新選處室」。
4. 跨樓層：先提示已確認的樓梯或入口，再呈現目標樓層，禁止只寫「往上走」。未確認的入口不生成精確轉向指示。
5. 最後一步：顯示「請確認現場門牌」與處室、建築、樓層。有已核對的入口照片才顯示，並區別外觀照片與處室入口照片。使用者確認後才結束。

## 內容與資料規則

- 共用既有房間固定 ID、建築、樓層與名稱，避免另一份處室主檔。
- 新增獨立的校門路線資料層：目的地 ID、來源、核對狀態、分段地標、動作、樓層、選用照片及照片說明。
- 註冊、轉學等別名須核對承辦單位及房間；核對前僅以已確認的處室名稱提供入口。
- 模型路徑只用於 3D 預覽，不直接轉成現場左右轉文字。導航階段模型可供分組，但實體路線需地標佐證。
- 尚未核對完整步行路線的地點仍可搜尋，顯示已知建築及樓層，明示「詳細步行指引尚未確認，請向警衛室詢問」，不提供假精確的下一步。
- 不以示意模型距離宣稱實際公尺或步行分鐘數，不將樓梯路線標成無障礙路線。
- 不蒐集家長姓名、電話或定位；本模式選擇和步驟僅保留在當次頁面操作中。

## 介面與架構

- 預期沿用 campus-data.js 的房間資料、field-guide.js 的入口與手冊整合方式，以及現有 3D 導覽 API；以最新發布來源重新核對後再定實際檔案切入點。
- 路線資料、路線卡狀態與畫面各自負責單一用途。狀態包含選擇、目的地確認、步驟、門牌確認與內容不足。
- 初次只顯示找處室所需內容；穿著、編輯、師生與煙火入口在此模式收起。結束模式可回到原探索介面。
- 3D 展開或關閉不重設路線卡；3D 人物抵達事件不推進實體路線卡。
- 支援目的地直連及重新整理；進度重新由正門開始，畫面明示起點。
- 常用處室採大按鈕，操作目標至少 44 CSS px；文字可放大，手機直橫向無水平溢出，底部按鈕避開安全區及鍵盤。
- 正式與 proposal 嵌入入口共用來源與同步流程，保留既有目的地連結、校慶首頁及瀏覽器自訂教室名稱。

## 分階段執行

1. 核對最新發布來源、正式及嵌入入口、處室資料與已有照片；建立可公開的目的地與路線核對表。
2. 完成校門入口、搜尋、路線卡與內容不足狀態；先接入有充分證據的處室。
3. 整合按需展開的 3D 預覽、手機介面與既有功能回歸檢查。
4. 提供預覽與驗證結果；公開發布按後續使用者指示執行。

## 驗收條件

- 從校門模式選常用處室，只需選地點及按一次開始，即顯示第一段指引。
- 搜尋能找到既有處室；未核對辦事別名不錯誤導向其他單位。
- 下一步與上一步只更新路線卡，不假稱定位或實際抵達；最後需使用者確認門牌。
- 缺照片、缺完整路線、未知目的地及 3D 載入失敗均有可繼續使用的明確狀態。
- 3D 未完成載入時可使用文字指引；預覽失敗不清除目的地或步驟。
- 以 320、390、430 CSS px 手機寬度及橫向驗證搜尋、鍵盤、長名稱、跨樓層與最後一步；煙火及其他工具不遮擋。
- 在正式及嵌入入口檢查目的地連結、首頁、原帶路及教室自訂值；完成相關資料與狀態測試及瀏覽器檢查。
