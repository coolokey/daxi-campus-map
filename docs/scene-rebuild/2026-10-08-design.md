# 校園場景移植與實景修正

使用者已授權分析、沿用複製資料夾程式並改善場景，包含美術模型協作。

## 分析

現版 `campus-data.json` 與 `campus-model.ts` 使用不同世界座標，搜尋聚焦不一致。行政前後棟並排、九年級棟橫向、藝術與綜合館順序反置，缺少實體樓梯、校門與柱列。複製版 `daxi-3d-campus/index.html` 已具可沿用的立體樓層、導航圖、角色、模型與控制。

複製資料夾中的 `future-campus-rpg` 則使用 React 與 Canvas 2D，具有房間切換、NPC 對話、收集晶片、班級挑戰、問答與學習摘要；`world-structure.ts` 分成校園、建築、樓層、房間、挑戰。這套資料結構可供後續教學任務擴充，但不是立體模型。此次直接沿用 3D 導覽場景，保留 RPG 原檔與學習資料。

## 方案

沿用複製版完整場景，作為 `public/campus-explorer` 獨立執行頁，由目前 React 入口載入。統一使用原場景配置及導航座標；保留原 React 頁面於 `LegacyCampusApp.tsx`，透過 `?viewer=legacy` 對照。舊目的地網址轉換為新場景目的地。移植來源唯讀保留於本目錄。

美術方向為暖灰校舍、陶土紅／米黃色屋頂、低飽和綠植栽與奶油色導覽介面。對照平面圖修正九年級班級樓層、東側館舍順序；對照實拍保留深色跑道與綠紅球場。平面圖提供配置與樓層，照片提供材質；尺寸為視覺示意，非工程測量。

## 實作與驗證計畫

1. 保存移植來源與舊入口；本地化 Three.js 與 OrbitControls。
2. 寫目的地相容與班級樓層／導航一致性測試，確認失敗後修正。
3. 分離場景程式與樣式；新增美術材質、景觀細節與導覽視角。
4. 新入口整合、加入平面圖／實拍對照與可存取操作。
5. 執行既有測試、打包，再以瀏覽器檢查鳥瞰、搜尋、導航、樓層、手機版，保存截圖與結果。

未修改 RPG 題庫、教師素材或公開部署。圖片模型生成圖只作美術輔助，不作地理校驗依據。
